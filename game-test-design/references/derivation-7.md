# 主动补充：7 条推导来源

补充项全部默认为“待确认”，不可直接升级为正式规则。

| # | 来源 | 反查内容 |
|---|---|---|
| 1 | 七问逐问反查 | 是否漏写开始、表现、数据、打断、失败、下一步或分支 |
| 2 | L1-L7 逐层反查 | 是否未定义某类打断的预期 |
| 3 | 影响面 8 类反查 | 是否只写自身，漏掉其他对象、同步、过滤或回滚 |
| 4 | 状态机完整性 | 是否缺迁移路径、异常态或终态 |
| 5 | 边界与极值 | 0、负数、极大、满值、空值是否未定义 |
| 6 | 并发与时序 | 同帧、多人与跨天/赛季/服切点是否未定义 |
| 7 | 失败与回滚 | 扣费成功但发奖失败、超时、重复提交怎么处理 |

## 三级分级

- 🔴 阻塞项：无法设计或无法判定通过/失败，确认前不生成用例。
- 🟡 风险项：可设计但处于高频缺陷区；未确认时显式标注假设。
- 🟢 优化项：体验或完备性问题，记录即可。

## 每条补充的三要素

① 来源位置（节/行/字段，精确可定位）；② 缺失、歧义或矛盾；③ 依据（命中上表第几条）。建议同时写“建议确认口径”和“状态：待确认”。
