# 交付前自检清单（单一闸门）

生成用例后、交付前，逐项过一遍。任一项不通过即回改，不交付。

## 1. UI 表现遗漏（见 ui-assertion.md 常见遗漏检查）

- [ ] 列表/卡片上的 icon、状态标志只验了显隐，没验资源对不对
- [ ] 空状态/加载失败/成功反馈只有文案预期，没有"icon + 布局"预期
- [ ] 弹窗/浮层只验了功能，没验视觉结构
- [ ] 交互键没对照图源确认 icon 形状与组合
- [ ] 独立小尺寸 icon 资源图集已建索引并对应到用例

## 2. 脚本化自检

- [ ] 正则扫**内部推演出处**残留：行为编号（`BEH-\d+`）/ 待确认编号（`C-\d+`、`N-\d+`）/ 行号 / xmind / 图锚点坐标。
  - ⚠️ **`imageNN` 图源引用不算残留**——它是 UI 断言的基准，允许且必需保留（区分口诀：把这句删掉，执行人还能不能照着测？能 → 只是说明出处，删；不能 → 他不知道对照哪张图，留）。
- [ ] Counter 查重复测试点。
- [ ] 统计否定类预期占比——纯 happy path 须明显低于分支失败类（目标 3:7）。

## 3. 图源读取率

- [ ] 图源读取率 = 100%（读图门禁见 SKILL.md SOP 第 2a/2 步）。
- [ ] 未读图须已在《待确认项清单》登记，并写明影响的用例范围与退化策略。

## 4. 三件套齐全

- [ ] `测试用例` + `待确认项清单` + `图源说明` 三者一并产出，缺一不可。
