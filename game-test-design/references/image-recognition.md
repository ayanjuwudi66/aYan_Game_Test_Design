# 图片材料识别（多模态优先，OCR 与像素分析兜底）

用户上传的需求材料**可能包含图片**（UI 原型图、交互示意图、数值表截图、竞品截图等），图内信息常为规则的唯一出处，**必须读到**。

## 降级链总览（逐级下探，每级都要留下可审计的产物）

| 级 | 手段 | 通过判据 | 必须落盘的证据 |
|---|---|---|---|
| **L0** | 多模态直读（含重试） | 图内文字/结构能转写 | 转写文本写入推演文档 Part A |
| **L1** | OCR（`rapidocr-onnxruntime`，原图 + 3x/5x 各跑一遍） | 有文字行输出 | `图源OCR结果.json`（含每行文本与置信度） |
| **L2** | 像素统计与差分定位（亮度 / 饱和度 / 近灰占比 / bbox） | 能得出可判定的量化结论 | 像素统计表（写入「图源说明」sheet） |
| **L3** | 用户代读：请用户提供图的文字版 / 更清晰切图 / 口头转述 | 用户给出信息 | 聊天记录 + 来源标注为"用户提供" |

- **每级结论必须引用落盘产物**（如"见 `图源OCR结果.json` image01 段"）。**没有产物 = 这一级未走过**，不得计入"已穷尽"——"我试过了"不构成证据。
- **L3 仍未读到**的图按「不可识别时」条款登记，不得口头一提就翻篇。

## L0 多模态直读（首选；失败必须重试，不是降级）

直接读图片文件，图内文字、UI 结构、布局关系、状态展示一并转写。

1. 传**绝对路径**直读，不要转成 base64 或走中间层。
2. **一次失败 ≠ 模型不支持**。报错后必须换方式重试，至少覆盖：直接读文件路径 / 转 PNG 或 JPEG / 缩小长边到 1024 / 大图分块裁切 / 新会话重读。
3. 换 ≥2 种方式仍失败，才可判定"多模态路径不可用"，进入下方兜底。

- **历史教训（2026-09-02 偷菜）**：首次读图被 "model does not support images" 拦截，判为不支持几乎放弃，整份用例差点漏掉图内规则；**随后同样文件、同样工具直接读，14 张全部成功**。首次失败是调用方式/间歇性问题，不是能力问题。把"一次失败"当成"模型不支持"，等于主动放弃信息量最大的路径。

## 兜底（L0 重试仍失败时才进；禁止直接放弃）

改用工程手段提取，两条路径覆盖两类信息：

1. **图内文字 → OCR**：`pip install rapidocr-onnxruntime`（自带模型，无需系统依赖）。对原图 + 放大 3x/5x 各跑一遍，按行聚类、同位置保留置信度高者，可显著提升小字与手写体准确率。
2. **视觉状态 → 像素统计与差异定位**：无文字的图（纯 icon/纯 UI）用平均亮度、平均饱和度、**近灰像素占比**、主色分布做量化；判定两张图是否为"同一界面的两个状态"时，做差分投影扫描，输出差异区块 bounding box 定位元素位置，再对该区域做亮度/饱和/灰化对比。

## xlsx 内嵌图导出

openpyxl 的 `img._data()` 会报 `I/O operation on closed file`，改用 `zipfile` 直接解包取 `xl/media/*`；再用 `xl/drawings/drawing1.xml` + `_rels` 解析 `twoCellAnchor` 的 col/row，建立「图 ↔ 工作表单元格 ↔ 邻近文字」映射，据此判断每张图的语义归属。

## 处理动作与来源标注

- 把图内可提取的规则**转写成结构化文字**，纳入「读取需求材料」环节，作为需求材料的组成部分。
- **来源标注（关键，延续严谨原则）**：图内**直接可见**的信息归入 **Part A（材料原样提取）**；基于图的**推断**（如"这个按钮大概代表某功能"）归入 **Part B（待确认）**，绝不写成确定预期。
- **多图对应**：一张图可能对应多个行为/多个节点。转写时按"每张图 + 涉及的行为/节点"分别记录，便于后续对应用例。
- **锚点可能错位**：图片在文档中的位置（行号/单元格锚点）与图的实际内容可能不一致（策划把图放错位置、或一张图被挪作他用）。读图后必须**以图的实际内容为准**重新判定语义归属，再对照邻近文字确认，不能盲信文档锚点行号。
- **兜底提取到的信息同样按 A/B 分栏**：OCR 直接读出的文字进 Part A；由像素指标反推的结论（如"暗态 = 压暗加降饱和"）进 Part B 并写明推导依据。

## 不可识别时

L1（OCR）与 L2（像素分析）**均无落盘产物**、且 L3（用户代读）也拿不到信息时，才可判定"该图信息无法可靠提取"，明确告知用户并请求补充，不得臆测。

- **没有产物 = 这一级未走过**，"我试过了"不构成证据；"模型不支持读图"本身不构成放弃的理由。
- **未读到的图必须留痕**，不许口头提一句就翻篇：在《待确认项清单》登记一条（阻塞级别按该图承载的规则条数定），并在「图源说明」中写明**影响的用例范围 + 退化策略**（降级为文案断言 / 该组用例暂停）。登记后按 SOP 第 2 步「读图门禁」交由用户选择是否带缺口继续。

## 告知义务（不可豁免）

只要材料里**有图**，而**任何一张没读到或没读全**，就必须**在对话中主动、明确地告诉用户**。写进交付文件（图源说明 / 待确认项清单）不算告知——用户很可能根本不会打开那个 Excel，写了等于没说。

- **两个时点都要说**：① 读图阶段一发现读不动，**立即**说，不等到交付；② 交付时再汇总一次，防止中途遗忘或中途有图被漏掉。
- **每次必须说清四件事**：
  1. **哪几张没读**——给图名/编号，不给"有部分图片"。
  2. **为什么没读**——降级链走到哪一级、卡在哪一步、报了什么错。
  3. **这几张可能承载什么规则**——按锚点邻近文字与文档上下文估；估不出来就写"未知"，**不许写"应该没什么重要信息"**（这是臆测，而且图内信息恰恰经常是唯一出处）。
  4. **建议怎么办**——补料后继续 / 带缺口继续 / 该组用例暂停，由用户选。
- **不许含糊带过**：禁止"图片信息已提取""已全部读取""大致看了下"这类笼统表述。**未读就是未读，不得计入已读**；宁可多说一句"有 3 张没读到"，也不要让用户以为读全了。
- **用户主动豁免也要留痕**：用户说"这几张不用读了"，仍须在图源说明标「未读（用户豁免）」并写明影响范围——下一个拿到这份用例的人不知道有过这次豁免，会以为漏测。
- **读了但质量存疑 = 未读全，同样要告知**：OCR 置信度低、像素反推、图内文字模糊有歧义的，一律按"未读全"处理：在图源说明标注、进 Part B 待确认，**不得当成确定事实写进用例预期**。

## 转写产物落盘

图片转写的文字整理进对应行为的推演文档（Part A / Part B 分栏），作为用例来源。**图内 UI（icon/布局/文案/状态视觉）另整理为"UI 表现清单"，作为 UI 用例的断言基准。**
