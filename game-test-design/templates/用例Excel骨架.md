# 用例 Excel 骨架

脚本 `scripts/gen_testcase_xlsx.py` 支持两种格式（`--format` 参数）：

- `--format skeleton`（默认）：**12 列内部骨架**，工作表 `TestCases`，供推演阶段使用。字段如下：

| 字段 | 说明 |
|---|---|
| 用例ID | 唯一标识 |
| 模块/功能 | 被测对象 |
| 状态节点 | 生命周期节点 |
| 前置条件 | 数据与环境 |
| 操作步骤 | 可执行步骤 |
| 预期结果 | UI、数据、同步与回滚 |
| 测试类型 | 主链路/分支/边界/回归等 |
| 打断层级 | L1-L7 或无 |
| 影响面 | 8 类对象，可多选 |
| 风险级别 | S1-S4 或自定义 |
| 优先级 | P0-P3 |
| 备注 | 弱网建议、假设、证据 |

- `--format delivery`：**7 列交付版**，即 SKILL.md「输出约定」规定的用户交付格式。输入 JSON 两种形态：
  - **纯用例**（对象数组）：只产 `测试用例` sheet，键为 `功能/测试点/操作步骤/预期结果/优先级`，脚本自动按连续相同「功能」合并功能列、备注与结果留空。
  - **三件套**（对象）：`{"cases": [...], "pending": [...], "img_notes": [...]}`，一步产出三个 sheet——
    - `测试用例`：7 列（功能/测试点/操作步骤/预期结果/备注/结果/优先级），功能列合并、备注结果留空
    - `待确认项清单`：7 列（编号/分类/待确认规则/疑问点/来源/影响行为/用例/默认处理(供参考)/状态）
    - `图源说明`：2 列（标题/内容）
  - 三件套是**标准交付形态**——待确认项与图源说明是交付物必要组成，不应在生成用例后单独手工补。

> **交付简化版**（用户要求简洁表格时，按 SKILL.md「输出约定」节转换）：
> `功能 | 测试点 | 操作步骤 | 预期结果 | 备注 | 结果 | 优先级`
> - 上表的 用例ID/状态节点/前置条件/测试类型/打断层级/影响面/风险级别 等**内部字段不直接展示**，其内容折叠进"操作步骤/预期结果/备注"对应位置（如打断信息并入步骤或备注）。
> - 备注与结果列交付时留空，由执行人填写；规则未拍板项另行单列《待确认项清单》。

> **交付简化版落地细则**（每次都会踩的四条）：
> 1. **功能列合并**：一个行为/模块一个合并区，不在每行重复写功能名；工作表用中文名，不用脚本默认的 `TestCases`。
> 2. **无前置列**：前置写进「操作步骤」首句，固定格式 `前置：<条件>。1. … 2. …`，保证每条用例可独立执行。
> 3. **备注留空与图源标注冲突时**：不要把"无独立 icon 图源"之类声明写进备注（备注必须留空给执行人），另建「图源说明」工作表统一声明缺口、受影响用例范围与退化策略。
> 4. **交付前脚本化自检**：① 正则扫正文残留出处标注（行为编号 / 待确认编号 / imageNN / 行号 / xmind）；② Counter 查重复测试点；③ 统计否定类预期占比——纯 happy path 须明显低于分支失败类（目标 3:7）。
