# 用例 Excel 骨架

脚本 `scripts/gen_testcase_xlsx.py` 支持两种格式（`--format` 参数）：

- `--format skeleton`（默认）：**12 列内部骨架**，工作表 `TestCases`，供推演阶段使用。字段如下：

| 字段 | 说明 |
|---|---|
| 用例ID | 唯一标识 |
| 模块/功能 | 被测对象 |
| 状态节点 | 生命周期节点 |
| 前置条件 | 数据与环境 |
| 操作步骤 | 可执行步骤 |
| 预期结果 | UI、数据、同步与回滚 |
| 测试类型 | 主链路/分支/边界/回归等 |
| 打断层级 | L1-L7 或无 |
| 影响面 | 8 类对象，可多选 |
| 风险级别 | S1-S4 或自定义 |
| 优先级 | P0-P3 |
| 备注 | 弱网建议、假设、证据 |

- `--format delivery`：**8 列交付版**，即 SKILL.md「输出约定」规定的用户交付格式。输入 JSON 两种形态：
  - **纯用例**（对象数组）：只产 `测试用例` sheet，键为 `功能/测试点/前提条件/操作步骤/预期结果/优先级`，脚本自动按连续相同「功能」合并功能列、备注与结果留空。
  - **三件套**（对象）：`{"cases": [...], "pending": [...], "img_notes": [...]}`，一步产出三个 sheet——
    - `测试用例`：8 列（功能/测试点/前提条件/操作步骤/预期结果/备注/优先级/结果），功能列合并、备注与结果留空
    - `待确认项清单`：7 列（编号/分类/待确认/来源/影响/默认处理/状态）
    - `图源说明`：2 列（标题/内容）。**必须含「读取状态总表」**（放在 sheet 开头），逐图声明读取情况——
      - 第 1 行为读取率声明，内容列固定格式：`图源读取率：已读 N / 共 M`
      - 其后每张图一行：标题列写图名，内容列按五段固定顺序写 `尺寸 | 读取方式 | 提取到的规则要点 | 未读原因 | 影响用例数`
      - 读取方式只能是：**多模态 / OCR / 像素 / 用户提供 / 未读**（五选一，不许含糊写"已处理"）
      - 出现「未读」行时，`pending` 中必须有对应登记条目，**否则交付不合格**
      - 示例：

        | 标题 | 内容 |
        |---|---|
        | 读取率 | `图源读取率：已读 12 / 共 14` |
        | image01 | 512×302 ｜ 多模态 ｜ 生长五阶段 0/33.3/40/66.7/100、保护时间 0:00-8:00 ｜ — ｜ 影响 12 条 |
        | image08 | 640×360 ｜ 多模态 ｜ 拳头 icon 亮态（金黄发光） ｜ — ｜ 影响 8 条 |
        | imageXX | 96×96 ｜ **未读** ｜ — ｜ OCR 无文字行、像素仅单一色块 ｜ 影响 3 条（退化为文案断言） |
  - 三件套是**标准交付形态**——待确认项与图源说明是交付物必要组成，不应在生成用例后单独手工补。

> **交付简化版**（用户要求简洁表格时，按 SKILL.md「输出约定」节转换）：
> `功能 | 测试点 | 前提条件 | 操作步骤 | 预期结果 | 备注 | 优先级 | 结果`
> - **列序（2026-09-03 修订）**：优先级在前、结果在后——优先级是**执行前**就要看的排期依据，结果是**执行后**才填的产出，按执行顺序从左到右排列；同时让"结果"落在最后一列，执行时视线从操作步骤一路向右到最末列打勾，不用回头。
> - 上表的 用例ID/状态节点/测试类型/打断层级/影响面/风险级别 等**内部字段不直接展示**，其内容折叠进"操作步骤/预期结果/备注"对应位置（如打断信息并入步骤或备注）。**「前置条件」是唯一保留展示的内部字段**——它独立成列，不折叠进操作步骤。
> - 备注与结果列交付时留空，由执行人填写；规则未拍板项另行单列《待确认项清单》。

> **交付简化版落地细则**（每次都会踩的四条）：
> 1. **功能列合并**：一个行为/模块一个合并区，不在每行重复写功能名；工作表用中文名，不用脚本默认的 `TestCases`。
> 2. **前提条件独立成列**（2026-09-03 修订，覆盖旧写法）：
>    - 旧写法 `操作步骤 = "前置：<条件>。1. … 2. …"` 已废弃——一列两责，执行人分不清"要准备什么"和"要做什么"，也无法按前置批量准备数据。
>    - 新写法：`前提条件` = 状态与环境（账号关系、次数余量、时段、对象状态、他人占用…），`操作步骤` = 纯动作（`1. … 2. …`）。
>    - **无前置时填"无"，不留空**，避免被误判为漏写。
>    - 存量数据迁移：脚本内置 `split_precondition()`，未提供 `前提条件` 键时自动从操作步骤首句「前置：…」拆分，老 JSON 可不改直接重跑。
> 3. **备注留空与图源标注冲突时**：不要把"无独立 icon 图源"之类声明写进备注（备注必须留空给执行人），另建「图源说明」工作表统一声明缺口、受影响用例范围与退化策略。
> 4. **单元格内换行**：`前提条件/操作步骤/预期结果` 含 `1. … 2. … 3. …` 多条时，必须在**同一单元格内**用换行符 `\n` 逐条断开，配合 `wrap_text + vertical: top`。脚本 `cell_break()` 自动完成：按序号标记（`1.` `2、` `3)` `4．` `5）`）前断行；序号后紧跟数字则不算序号（`3.5 秒`、`40.50%` 不切）；「第2.」不切；无序号仅用「；」分隔的保持原样，不臆测拆分。
> 5. **交付前脚本化自检**：
>    ① 正则扫**内部推演出处**残留：行为编号（`BEH-\d+`）/ 待确认编号（`C-\d+`、`N-\d+`）/ 行号 / xmind / 图锚点坐标。
>       **⚠️ `imageNN` 图源引用不算残留**——它是 UI 断言的基准，SKILL.md「UI 表现校验」节要求 UI 用例必须标注对照图源，**允许且必需保留**（区分口诀：把这句删掉，执行人还能不能照着测？能 → 只是说明出处，删；不能 → 他不知道对照哪张图，留）。
>    ② Counter 查重复测试点；
>    ③ 统计否定类预期占比——纯 happy path 须明显低于分支失败类（目标 3:7）；
>    ④ **图源读取率 = 100%**（读图门禁见 SKILL.md SOP 第 2a/2 步）；未读图须已在《待确认项清单》登记，并写明影响的用例范围与退化策略。
